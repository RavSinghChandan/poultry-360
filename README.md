# 🐔 Poultry 360

A 360° assistant for Indian poultry farmers, built the **harness way** —
the model is one step inside a loop we control.

**Feature 1 (live):** enter a bird's age, get the exact ration — protein,
energy, amino acids, and how much feed the batch needs today. Every number
traced to a published standard.

## Run

```bash
./run.sh
```

Open **http://localhost:8000** — Hindi + English, built for a phone.

## Test

```bash
.venv/bin/python -m pytest tests/ -q
```

211 tests: data correctness, domain arithmetic, authority, budgets, farm
sign-in, and the seams between them.

## Farms sign in (multi-tenant)

1. A farm registers at `/register` (farm name, owner, phone, district).
2. The owner approves it at `/admin` and gets a **tenant key + username**, with a
   one-click sign-in link to send by WhatsApp or email.
3. The farm opens the link (or types the key) and is signed in for 7 days.

Tenant keys and sessions are HMAC-signed, so approved farms can sign in even
after a free-tier restart wipes the disk. Reading tips and schedules stays open;
every feature action needs a signed-in farm, within daily caps per farm, per
network and for the whole app. Sign-in is off locally (`POULTRY_AUTH=on` to try
it) and always on in production (`POULTRY_ENV=production`, or any Render deploy).

Each flow is drawn as a chakra: every step is a node on the wheel, and the step
the farmer is on lights up, in Bengali, Hindi or English.

## Deploy

One Docker image serves the API and the UI on one port. On Render: **New →
Blueprint →** this repo ([render.yaml](render.yaml)), then optionally paste a
`DEEPSEEK_API_KEY`. The admin key is generated by Render (Environment tab).

## Where the numbers come from

NRC *Nutrient Requirements of Poultry* (1994) Table 5-1, and BIS IS 1374:1992.
The agent looks them up and explains them. It never invents one — see
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
